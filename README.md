# YA Travel Design

Telegram-бот `@yatraveldesign_bot` публикует ZIP-прототипы в этот репозиторий и выдаёт команде каталог versioned skills. Бот сохраняет контент в ветке `main`; workflow собирает каталог `public/` и публикует его через GitHub Pages.

## Что делает меню

- **Опубликовать прототип** — принимает ZIP со статическим HTML, проверяет архив, добавляет его в каталог и публикует по пути `prototypes/<telegram-id>/<имя-архива>/`.
- `/prototypes` — показывает 15 последних прототипов.
- `/delete_prototype` — общий список прототипов с выбором и подтверждением удаления.
- `/delete_skill` — общий список скиллов с выбором и подтверждением удаления.
- **Menu → Skills** — открывает Telegram Web App с карточками скиллов, промптом первого подключения и ссылкой на установку в ChatGPT на Mac.
- ZIP или `SKILL.md` можно прислать прямо в чат. ZIP с несколькими `SKILL.md` публикуется целиком как один пакет. Если в корне комплекта есть `README.md` и `install.py`, Store предлагает установку через `install.py --check`, затем `install.py`; иначе выдаёт инструкцию распаковать содержимое в папку skills. Для одиночного скила одинаковое поле `name` обновляет существующий skill, а не создаёт дубликат.

## Первый запуск

1. В GitHub: **Settings → Pages → Build and deployment → GitHub Actions**.
2. На домашнем Mac бот использует существующий SSH-доступ этого Mac к GitHub. Отдельный GitHub token не нужен; deploy key можно добавить позднее, если доступ нужно ограничить одним репозиторием.
3. Telegram token хранится в macOS Keychain под service name `yatraveldesign-bot-token`, вне Git. Шаблон `launchd/com.yuriysteam.yatraveldesign-bot.plist` запускает бота при входе в macOS.
4. Укажите `PUBLIC_BASE_URL`: URL GitHub Pages или собственный домен.

- У каждого нового скила в frontmatter `SKILL.md` обязательна версия формата `version: v0.1`; Store берёт её из этого поля и показывает рядом с датой обновления.

## Границы

- Максимальный ZIP — 20 МБ, после распаковки — 100 МБ и до 2 000 файлов.
- Бот хранит локально только служебную SQLite-базу с обработанными Telegram updates и незавершёнными загрузками; skills и прототипы остаются в GitHub.
- Skills не выводятся на странице прототипов, но ZIP каждого skill публично доступен по прямой ссылке GitHub. Git хранит историю обновлений.

## Отбивки в командную группу

В группах бот игнорирует входящие сообщения, файлы и callback-кнопки. Загрузки и меню работают только в личке.
Рядом с SQLite-файлом состояния положите локальный `publication-chat.json` с числовым `chat_id` группы.
После подтверждённой публикации бот отправляет в группу карточку скила с кнопкой копирования промпта установки. Для обновления существующего скила текст карточки — «Обновился скилл Имя» без описания; для нового — «Новый скил Имя» и описание. Ошибки публикации остаются в личных уведомлениях. Ошибка доставки в группу не запускает публикацию повторно; автоматической повторной доставки пока нет.

## Публикация и удаление

Действия с контентом доступны пользователям из `ALLOWED_USER_IDS` в личном чате. Удалять можно контент любого автора. Списки удаления разбиты на страницы по 15 элементов. При подтверждении бот заново читает каталог, удаляет файлы выбранного элемента и его запись в `prototypes.json` или `skills/catalog.json` одним Git-коммитом. Если от скилла зависят другие скиллы, удаление блокируется с их названиями.

При публикации прототипа бот редактирует одно сообщение: «Загружаю файл…» → «Проверяю архив…» → «Проверяю прототип…» → «Загружаю на сервер…» → «Жду публикацию страницы…». Финальный текст — `Загружено ✓`, пустая строка и URL — появляется только после HTTP 200 от публичной страницы. Отдельного сообщения «Готово» нет; при неуспехе исходное сообщение содержит ошибку без успешной ссылки. Для скиллов сначала выполняется проверка и подтверждение/настройка пользователем, затем публикация с понятными статусами; финальный статус не содержит непроверенную ссылку.

Мониторинг ожидает workflow `Publish prototypes` для точного коммита и проверяет публичный результат. Если GitHub Actions недоступен из-за лимита API, проверка публичного результата служит запасным подтверждением. При сбое допускается до двух повторных деплоев через `pages-retry.txt`. Удаление прототипа подтверждается HTTP 404 страницы; удаление скилла — отсутствием в публичном каталоге и HTTP 404 ZIP. Ошибка подтверждения отображается как ошибка удаления.

Telegram HTTP-ошибки записываются с названием метода и пояснением API без токена. Просроченный `answerCallbackQuery` не блокирует очередь обновлений: обработанный update сохраняется в SQLite и не выполняется повторно.

## Установка скиллов

Skill Store и карточки бота предлагают промпт установки исходного ZIP. Зависимости разрешаются через `skills/catalog.json`; архив распаковывается целиком. Для комплектов с `install.py` сначала выполняется `python3 install.py --check`, затем `python3 install.py`; конфликты не заменяются. Авторский промпт может заменить автоматический.

Проверки: `/usr/bin/python3 -m unittest -v test_bot.py` и `node --test test_store.js`. Локальный просмотр: `python3 -m http.server 8765 --bind 127.0.0.1`, страница `/skills/`.
