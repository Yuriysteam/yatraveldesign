# Командировки — вариант 2

Отдельный интерактивный прототип командировок. Главная и сценарии отелей, авиа и ж/д переиспользованы из первого варианта. Новый экран командировки держит верхнюю часть на месте, а все действия по поиску и бронированию показывает в нижней области.

## Запуск

Из папки прототипа:

```bash
python3 -m http.server 4175
```

Открыть:

```text
http://localhost:4175/index.html
```

Прототип нужно открывать через локальный сервер, а не через `file://`.

## Что реализовано

- «Создать» на главной открывает новый [trip.html](./trip.html).
- Верхняя часть командировки остаётся на экране при переключении между авиа, поездами и жильём.
- Готовые сценарии бронирования работают в нижней области без своей старой шапки и стартовой поисковой формы.
- Клик по сводке маршрута открывает список услуг с плавным появлением.
- «Добавить услуги» открывает выбор вертикали; масштабируется только фон списка услуг.
- После завершения бронирования услуга возвращается в текущую командировку без вложенного второго `trip.html`.
- Услуги можно удалить и выбрать заново; отдельная или общая оплата открывается в нижней области.
- Черновики, оплаченные и отменённые поездки появляются на главной и в списке поездок.
- Отменённая командировка открывается только для просмотра.

{% note info %}

Это статический прототип. Оплата, бронирование и действия шапки не отправляют данные во внешние системы.

{% endnote %}

## Как устроен экран командировки

```text
trip.html
├─ постоянная верхняя часть
│  ├─ маршрут, даты, пассажиры и счётчик услуг
│  ├─ Авиа / Поезда / Жильё
│  └─ поисковые поля активной вертикали
├─ нижняя область бронирования
│  ├─ same-origin iframe с существующим сценарием
│  └─ проверка и оплата выбранных услуг
└─ список услуг
   ├─ добавленные услуги
   ├─ выбор новой услуги
   └─ переход к проверке и оплате в нижней области
```

Параметр `embed=trip-v2` включает встроенный режим нижних страниц. Завершённый сценарий отправляет родительской оболочке только результат новой услуги. Состояние списка услуг, удаления, оплаты и жизненного цикла остаётся под управлением `trip.html`, поэтому старый открытый экран бронирования не может откатить более свежие изменения.

## Состояние

- Основной переносимый контракт хранится в query-параметрах URL.
- Нормализованный список услуг хранится в `tripServices`.
- Черновики, оплаченные и отменённые поездки сохраняются локально в браузере.
- Все ключи варианта 2 имеют суффикс `-v2`; данные первого прототипа не меняются.
- Данные пассажиров и выбранные места отдельных сценариев временно хранятся в `sessionStorage`.

## Основные проверки

1. На главной выбрать «Командировка», маршрут, даты и нажать «Создать».
2. Переключить авиа, поезда и жильё — верхняя часть должна остаться на месте.
3. Нажать на сводку маршрута — должен открыться список услуг.
4. Добавить услугу через нижний сценарий — она должна появиться в списке и счётчике.
5. Удалить неоплаченную услугу и выбрать её заново.
6. Открыть оплату услуги — проверка и действие должны появиться в нижней области; после оплаты черновик должен смениться оплаченной поездкой.
7. Отменить командировку — действия редактирования и оплаты должны стать недоступны.

## Ограничения

- Серверной части и реальной оплаты нет.
- Данные доступны только в текущем браузере и origin.
- Прототип рассчитан прежде всего на настольный экран шириной около 1440 px.
