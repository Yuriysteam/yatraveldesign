# Прототип создания командировки

Интерактивный статический прототип полного сценария командировки: создание таймлайна, добавление отеля, авиабилетов и ж/д билетов, возврат выбранных услуг в командировку, удаление отдельных сегментов и состояние оплаты.

{% note info %}

Это прототип без сервера и реальной оплаты. Основное состояние передаётся через параметры URL, данные пассажиров и выбранные места временно сохраняются в `sessionStorage`. Бронирования, платежи и действия шапки не отправляются во внешние системы.

{% endnote %}

## Быстрый запуск

Из этой папки:

```bash
python3 -m http.server 4174
```

Открыть:

```text
http://127.0.0.1:4174/index.html
```

Прототип лучше проверять через локальный сервер, а не через `file://`: так переходы, ресурсы и состояние между страницами работают одинаково.

## Основной сценарий

1. На главной пользователь выбирает вертикаль «Командировка», направление, даты и пассажиров.
2. «Создать» открывает незаполненную командировку с постоянным таймлайном:
   - транспорт туда;
   - жильё;
   - транспорт обратно, если задана обратная дата.
3. Из пустой секции пользователь запускает поиск нужной услуги.
4. После выбора и заполнения данных услуга возвращается в соответствующую секцию таймлайна.
5. Стоимость пересчитывается по добавленным услугам. Для услуг со статусом «Ожидает оплаты» запускается таймер.
6. Удаление очищает только выбранную секцию и показывает в ней исходную карточку выбора. Остальной таймлайн и второй транспортный сегмент сохраняются.

Основные ветки:

```text
Главная
  └─ Командировка
       ├─ Отель: поиск → отель и тариф → оформление → командировка
       ├─ Авиа: выдача → пассажир → подтверждение → командировка
       └─ Ж/д: выдача туда → места туда
              ├─ one-way → пассажиры → командировка
              └─ roundtrip → выдача обратно → места обратно → пассажиры → командировка
```

## Общие механики

### Состояние и навигация

- Главный контракт между страницами — query-параметры URL.
- Все переходы сохраняют базовые параметры маршрута и добавляют данные выбранной услуги.
- Страницы можно перезагрузить или открыть по прямой ссылке: маршрут и большинство параметров услуги восстановятся из URL.
- Чувствительные к форме данные — пассажиры, контакты и ж/д места — дополнительно хранятся в `sessionStorage` текущей вкладки.
- Сервер, база данных и сетевые запросы не используются.

### Направления

- Поля поддерживают ввод, фильтрацию подсказок и клавиатурную навигацию.
- Для отелей и ж/д используются города.
- Для авиа используются города и аэропорты с кодами.
- Кнопка обмена меняет направления местами.

### Даты

- Во всех поисковых формах используется один календарь диапазона.
- Первый выбор задаёт дату начала и оставляет календарь открытым.
- Второй выбор задаёт дату окончания и закрывает календарь.
- Начало, конец и промежуток диапазона подсвечиваются в одном календаре.
- `depart` и `return` задают общие границы командировки и не меняются при перепоиске отдельной услуги.
- Отель, авиа и ж/д хранят собственные даты. Поэтому между перелётом, проживанием и обратным транспортом могут оставаться дни без услуги.
- Для авиа и ж/д можно выбрать поездку в одну сторону. Тогда обратная дата и данные обратного сегмента удаляются.

### Пассажиры

- Базовое состояние — один взрослый.
- Главная передаёт одновременно числовые `adults`/`children` и готовую подпись `traveller`.
- Пассажирские формы подставляют демонстрационные профили и контактные данные.

### «Еду по работе»

- На главной переключатель показывается в вертикалях отелей, авиа и ж/д.
- Обычная кнопка поиска жёлтая.
- При включённом переключателе кнопка становится тёмной, а в URL появляется `workTrip=1`.
- Переключатель меняет визуальное состояние прототипа, но не отправляет данные во внешнюю систему.

### Шапка

- Поисковые и оформительские страницы используют общую шапку из [shared-search-header.js](./shared-search-header.js) и [shared-search-header.css](./shared-search-header.css).
- Иконки имеют фиксированные размеры; красная точка у аватара скрыта.
- Переходы шапки, для которых нет отдельного сценария, остаются заглушками.

### Сообщения

- Постоянного тоста `#toast` нет.
- Служебные действия могут обновлять невидимую область `aria-live` для доступности.
- Прототип не показывает всплывающее сообщение на каждое действие.

## Главная

### Вертикали

- Базово выбраны отели.
- Отели, авиа и поезда меняют состав поисковой формы и адрес следующего экрана.
- «Командировка» показывает форму создания командировки и блоки «Мои командировки» и «Согласования».
- «Мои командировки» и «Согласования» скрыты во всех остальных вертикалях.
- Туры и услуги сейчас добавляют демонстрационные карточки на главную и не открывают отдельный сценарий.
- Частое направление переключает форму на отели и подставляет выбранный город.
- Действие согласования меняет только локальное состояние кнопки.
- Главная не восстанавливает маршрут и даты из query-параметров при повторном открытии: они используются после отправки формы на следующих экранах.
- `reference=1` включает служебное референсное состояние с несколькими одновременно открытыми подсказками и не является пользовательским сценарием.

### Отправка формы

| Вертикаль | Следующий экран | Дополнительное состояние |
|---|---|---|
| Отели | `hotel-search.html` | `city`, `checkin`, `checkout` |
| Авиа | `avia-search.html` | `flightOutboundDate`, `flightReturnDate`, `flightScope=roundtrip\|oneway` |
| Поезда | `train-search.html` | `railOutboundDate`, `railReturnDate`, `railScope=roundtrip\|oneway` |
| Командировка | `trip.html` | Пустой таймлайн по маршруту и датам |

Во всех ветках передаются `from`, `to`, `depart`, `return`, `adults`, `children` и `traveller`.

## Страница командировки

## Список командировок

- Иконка «Мои поездки» в шапке открывает `trips.html` — раздел «Командировки».
- Оплаченные командировки показаны во вкладках «Предстоящие», «Активные» и «Прошлые»; карточка открывает заполненную страницу конкретной командировки.
- Отменённые командировки отображаются только во вкладке «Отменённые» и остаются в режиме просмотра.

### Структура таймлайна

- Секция «туда» всегда присутствует.
- Секция жилья всегда присутствует.
- Секция «обратно» присутствует только при валидной обратной дате.
- Пустая секция показывает доступные действия.
- Заполненная секция показывает карточку услуги, статус и кнопку удаления.
- Если транспорт выбран, заголовок становится «Самолёт в …» или «Поезд в …»; для обратного сегмента — с городом возвращения.
- Дата у заполненного транспортного сегмента берётся из выбранного рейса или поезда, а не из границы командировки.
- Если проживание начинается не в день прибытия, жильё получает отдельную дату в таймлайне; карточка показывает весь диапазон проживания.

### Пустые состояния

- «Авиа» открывает авиа-выдачу.
- «Ж/д» открывает ж/д выдачу для нужного сегмента.
- «Найти жильё» открывает поиск отелей с городом назначения и начальными датами из командировки. Их можно изменить перед выбором отеля.
- «Не нужно» только переключает локальное состояние секции.

### Карточки услуг

- На наведении интерактивная карточка получает подсветку.
- Клик или Enter отправляет событие `trip:service-details`.
- Отдельная страница деталей услуги пока не подключена.
- Авиа и ж/д туда-обратно считаются одной услугой по стоимости, но показываются двумя карточками в таймлайне.

### Удаление

- Кнопка «Удалить» очищает только свою секцию.
- Таймлайн и заголовок секции остаются на месте.
- Вместо услуги появляется исходная карточка выбора.
- При удалении одного транспортного сегмента второй сохраняется и становится самостоятельной one-way услугой.
- Состояние записывается в URL:
  - `outboundRemoved=1` — удалён транспорт туда;
  - `lodgingRemoved=1` — удалено жильё;
  - `returnRemoved=1` — удалён транспорт обратно.
- Новый выбор услуги снимает соответствующий флаг удаления.

### Статусы и оплата

| Значение в URL | Подпись |
|---|---|
| `awaiting-payment` | Ожидает оплаты |
| `paid` | Оплачена |
| `out-of-policy` | Не в тревел политике |

- Для услуг, ожидающих оплаты, запускается рабочий таймер на 12 минут.
- Таймер обновляется каждую секунду и после истечения блокирует кнопки оплаты.
- Время не сохраняется: после перезагрузки таймер начинается заново.
- У оплаченных услуг нет кнопки оплаты. Если появляется хотя бы одна новая услуга со статусом `awaiting-payment`, в корзине появляется кнопка «Оплатить».
- «Оплатить» отправляет событие `trip:payment-requested`, но реальной оплаты и перехода пока нет.
- Итоговая стоимость пересчитывается после добавления и удаления услуг.

### Приоритет транспортных данных

Если в URL одновременно остались `railAdded=1` и `flightAdded=1`, страница показывает ж/д. Это защита от смешивания двух незавершённых транспортных сценариев, а не выбор пользователем двух видов транспорта в одной секции.

## Сценарий отеля

```text
trip.html
  → hotel-search.html
  → hotel.html
  → hotel-checkout.html
  → trip.html
```

### 1. Поиск отелей

- Форма принимает город, заезд, выезд и гостей из параметров командировки.
- Один календарь выбирает обе даты.
- «Найти» имитирует перепоиск: обновляет только `checkin`/`checkout`, число ночей и локальную выдачу без сетевого запроса. Общие `depart`/`return` сохраняются.
- Работают сортировки по рекомендации, цене и рейтингу.
- Работают фильтры по цене, типу размещения, звёздам, рейтингу, расположению и удобствам.
- «Умный фильтр» включает корпоративный тариф, завтрак, бесплатную отмену, Wi-Fi и рабочий стол и оставляет варианты в политике.
- Наведение на карточку выделяет соответствующую метку на карте.
- Клик по метке прокручивает выдачу к карточке.
- Клик в любую область карточки или «Выбрать» сразу открывает страницу отеля.
- Избранное, масштаб карты и разворачивание карты работают только в текущем DOM.

### 2. Страница отеля

- Название, рейтинг и город берутся из URL.
- Адрес должен соответствовать выбранному городу. Несовместимый адрес заменяется локальным адресом города.
- Показаны статичные типы номеров и тарифы с ценой, рассчитанной от выбранного отеля.
- «Подробнее» раскрывает описание номера.
- Галерея открывается модально и поддерживает клавиатуру.
- «Поделиться» копирует текущую ссылку.
- Избранное и уведомления — локальные переключатели.
- Выбор тарифа открывает оформление и передаёт отель, номер, тариф, цену и статус.

### 3. Оформление отеля

- Показаны даты, гость, выбранный номер, условия, правила проживания и поле пожеланий до 500 символов.
- Можно раскрыть детализацию цены.
- Режим начисления баллов только показывает будущие баллы.
- Режим списания уменьшает итог максимум на 1 000 ₽.
- Промокод `TRAVEL10` уменьшает базовую цену на 10%; другие значения показывают ошибку.
- «Добавить в командировку» передаёт итоговую цену и `hotelStatus` на `trip.html`.
- Непустое пожелание передаётся как `hotelWish`, но в карточке командировки пока не показывается.

### Ограничения ветки отеля

- Каталог, изображения и базовые цены статичны; выбранный город меняет контекст, но не источник данных.
- Переключатель цены «за ночь» пока не участвует в фильтрации.
- На странице отеля даты не редактируются.
- Подтверждение бронирования и оплата не отправляются.

## Сценарий авиа

```text
trip.html
  → avia-search.html
  → avia-passengers.html
  → avia-confirmation.html
  → trip.html
```

### 1. Выдача авиабилетов

- Поддерживаются `roundtrip` и `oneway`.
- Единый календарь выбирает вылет и возвращение; «Без обратного билета» очищает обратную дату.
- «Найти» имитирует перепоиск и обновляет `flightOutboundDate`/`flightReturnDate`, не меняя общие даты командировки.
- Работают сортировки по популярности, цене и времени в пути.
- Работают быстрые фильтры «Без пересадок» и «С багажом» и расширенные фильтры по пересадкам, времени, аэропортам и авиакомпаниям.
- Карточка показывает одно плечо для one-way и два плеча для roundtrip.
- Выбор карточки сразу открывает данные пассажира с параметрами обоих плеч.

### 2. Тариф и данные пассажира

- Доступны тарифы `light`, `optimum` и `maximum`.
- Пассажирская форма содержит ФИО латиницей, дату рождения, пол, документ, страну, программу лояльности, email и телефон.
- Демонстрационные профили подставляют одновременно пассажира и контакты.
- Работают маски и валидация обязательных полей.
- Черновик формы хранится в `sessionStorage` отдельно для выбранного рейса и типа поездки.
- После проверки создаётся `bookingId`, снимок подтверждения и переход на следующий экран.

### 3. Подтверждение

- One-way показывает один сегмент, roundtrip — два.
- Показаны маршрут, перевозчики, времена, условия тарифа, пассажир и итоговая цена.
- «Добавить в командировку» сохраняет снимок бронирования, ставит `flightAdded=1` и открывает `trip.html`.
- В командировку услуга приходит со статусом `flightStatus=awaiting-payment`.

### Ограничения ветки авиа

- Выдача состоит из статичного демонстрационного набора.
- Все текущие варианты прямые и без багажа, поэтому фильтр «С багажом» даёт пустую выдачу.
- Выбор города пересадки показан в интерфейсе, но пока не влияет на фильтрацию.
- Параметр `segment` сохраняется между страницами, но выдача пока выбирает целый one-way или roundtrip комплект, а не отдельное плечо.
- При нескольких пассажирах экран всё равно создаёт форму только одного взрослого.
- Переход на подтверждение требует снимок пассажира в `sessionStorage`; прямой вход с реальным `flight` без снимка покажет ошибку.
- Проверка данных и добавление имитируются короткими задержками, сетевых операций нет.

## Сценарий ж/д

### Туда-обратно

```text
train-search.html?railSegment=outbound
  → train-booking.html?railSeatSegment=outbound
  → train-search.html?railSegment=return
  → train-booking.html?railSeatSegment=return
  → train-passengers.html
  → trip.html
```

После выбора мест туда пользователь возвращается на выдачу поездов обратно. На обратной выдаче поисковая форма скрыта, потому что направление и дата уже заданы командировкой.

### В одну сторону

```text
train-search.html?railSegment=outbound
  → train-booking.html?railSeatSegment=outbound
  → train-passengers.html
  → trip.html
```

### 1. Выдача поездов

- Форма повторяет маршрут, даты и пассажиров командировки; перепоиск меняет только `railOutboundDate`/`railReturnDate`.
- В ж/д используются полные названия городов и станций без авиационных сокращений вроде `MOW`.
- Карточки не отделяются дополнительной тенью на наведении.
- Выбор поезда сохраняет номер, перевозчика, время, длительность, станции и цену активного сегмента.
- Если пользователь меняет поезд, ранее выбранные места и стоимость этого сегмента сбрасываются.

### 2. Выбор мест

- Доступны плацкарт, купе, СВ и люкс.
- Смена типа вагона сбрасывает выбранные места активного сегмента.
- Количество обязательных мест равно числу взрослых и детей с местом.
- Нельзя выбрать недоступное место или одно и то же место в разных вагонах.
- Можно включить постельное бельё; оно влияет на итоговую цену.
- Пассажиры разделены на взрослых, детей с местом и детей без места.
- Максимум пассажиров с местом — шесть; детей без места не может быть больше, чем взрослых.
- Выбор, вагон и цена сегмента синхронизируются с URL и `sessionStorage`.
- «Изменить поезд» возвращает на выдачу нужного сегмента.

### 3. Данные пассажиров

- Экран собирает поезд туда и, для roundtrip, поезд обратно из URL и сохранённого снимка.
- Для каждого пассажира доступны профиль, ФИО, дата рождения, пол, документ и номер программы РЖД.
- Контактные данные форматируются и проверяются.
- «Изменить места» возвращает к выбору мест.
- «Добавить в командировку» сохраняет завершённое бронирование, ставит `railAdded=1`, `railStatus=awaiting-payment`, итоговую цену и открывает `trip.html`.
- Временные параметры выбора очищаются перед переходом в командировку.
- Авиационные параметры также очищаются, чтобы транспортные сценарии не смешивались.

### Ограничения ветки ж/д

- Поезда, вагоны и доступность мест — демонстрационные данные.
- Бронирование мест и оплата не отправляются перевозчику.
- Снимок ж/д сценария привязан к `railBookingId` и текущей вкладке браузера.

## Контракт параметров URL

### Маршрут

| Параметр | Значение |
|---|---|

| `workTrip=1` | Включён переключатель «Еду по работе» |

| `railScope` | `roundtrip` или `oneway` для ж/д |

|---|---|

| Параметр | Значение |
|---|---|

## Данные в sessionStorage

| Ключ | Что хранится |
|---|---|
| `business-trip-avia-passenger-draft-v1:{flightId}:{scope}` | Черновик авиаформы |
| `business-trip-avia-confirmation-v1` | Пассажир, контакты, рейсы и тариф для подтверждения |
| `business-trip-avia-booking-v1` | Добавленное в командировку авиа-бронирование |
| `rail-booking:{railBookingId}` | Поезда, места, пассажиры, контакты и итог ж/д сценария |

`localStorage` не используется. После закрытия вкладки сохранённые снимки могут быть потеряны.

## Проверочные сценарии

1. Создать пустую командировку туда-обратно и убедиться, что видны три секции таймлайна.
2. Добавить отель, вернуться в командировку и удалить его: секция жилья должна остаться пустой.
3. Добавить roundtrip авиа: в таймлайне должны появиться два сегмента и одна общая цена.
4. Удалить только обратный авиасегмент: сегмент туда должен остаться, обратная секция — стать пустой.
5. Создать one-way авиа: обратная секция и обратные параметры не должны появиться.
6. Выбрать поезд туда и места: следующий экран должен быть выдачей поездов обратно без поисковой формы.
7. Выбрать места обратно, заполнить пассажира и добавить ж/д: в командировке должны появиться две ж/д карточки.
8. Дождаться завершения таймера: кнопки оплаты должны заблокироваться.
9. На главной переключать вертикали: «Мои командировки» и «Согласования» должны быть только в «Командировках».
10. Для командировки 4–10 августа выбрать транспорт туда 4-го, отель 5–7-го и транспорт обратно 9-го: заголовок должен сохранить 4–10 августа, а таймлайн — показать даты каждой услуги и разрывы между ними.

## Точки расширения

Страница командировки экспортирует `window.TripPagePrototype`: модель, перерисовку, смену статуса, оплату и удаление секций. Для подключения следующих экранов можно слушать события:

- `trip:service-details` — клик по заполненной услуге;
- `trip:payment-requested` — запрос оплаты одной услуги или всех услуг.

Эти события позволяют добавить детали и оплату без переписывания карточек таймлайна.
