# Internal Research

Исследуй внутренние сервисы через настроенные CLI, API и локальные checkout. До первого использования попроси пользователя указать доступные инструменты, корень актуального checkout и правила авторизации. Не сохраняй токены, cookies, ключи или вывод авторизации.

## Порядок работы

1. Зафиксируй источник, ревизию или дату проверки.
2. Для задач используй корпоративный трекер через CLI или API.
3. Для кода и истории используй актуальный локальный checkout и его штатный VCS-клиент.
4. Для ревью сначала восстанови изменения по коду и коммитам; веб-интерфейс открывай только для данных, которых нет в CLI.
5. Для внутренней документации используй доступный корпоративный источник, а не публичный поиск как замену.

## Проверка и вывод

- Отделяй текущий код, конфигурацию по умолчанию, экспериментальные настройки и наблюдаемое поведение в продакшене.
- Не считай пустую настройку доказательством выключенного поведения, если её можно переопределить.
- Для каждого важного вывода оставляй проверяемую ссылку, путь к файлу, задаче, ревью или коммиту.
- Отдельно перечисляй ограничения проверки и неизвестные значения.
- При исследовании ничего не изменяй во внутренних сервисах без отдельной просьбы.
