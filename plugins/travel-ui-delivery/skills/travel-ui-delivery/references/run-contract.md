# Контракт запуска

## Вход пользователя

Разрешены свободный текст и короткая форма:

```yaml
ticket: TRAVELAPP-1234
figma:
  - https://www.figma.com/design/...?...node-id=123-456
platforms: [ios, android, web] # либо auto
mode: analyze | draft | deliver
notes: |
  Что должно измениться и какие состояния важны.
evidence_bundle: null # сохранённый пакет только для replay/analyze
live_access: allowed # либо forbidden
```

Матрица обязательных входов:

- `analyze`: `ticket` или `figma`;
- `draft`: точный Figma-узел; `ticket` может быть `none`;
- `deliver`: тикет и точный Figma-узел.

`evidence_bundle` не разрешает live-доставку без проверки актуальных источников.

## Пакет штатному агенту платформы

- `platform` и штатный агент из таблицы ниже;
- `worktree_path` и `branch`;
- `ticket` или `none` и точные Figma-ссылки;
- `intent`;
- матрица состояний и значимых контекстов;
- `allowed_paths` без директорий, glob и `..`;
- `platform_gate`: статус, точные источники правил, runtime-контракт, цепочки переопределения, план переиспользования, перекрёстные сценарии и результаты предварительной проверки среды;
- найденные компоненты для переиспользования;
- обязательные проверки и семейства снимков;
- решения пользователя и ограничения.

| Платформа | Штатный агент | Обязательные локальные правила | Снимки |
|---|---|---|---|
| iOS | `ios-coder` | `travel-ios-architecture`; для UIBase по Figma — `figma-ds-component` | Текущий XCTest snapshot-процесс проекта |
| Android | `coder` | `how-to-ui`, `travel-android-architecture`; для DS — `generate-ds-component` и `validate-ds-component-figma` | Текущий Paparazzi/Compose-процесс проекта |
| Web | `worker-bee` | пресет `travel/frontend/dev-common` и его актуальные правила | Текущий Storybook/визуальный процесс сервиса |

Оркестратор передаёт этот пакет штатному агенту напрямую. Промежуточный платформенный адаптер не создаётся.

## Единый контракт реализации

Штатный агент платформы:

1. До правок сверяет `platform_gate` с актуальным checkout: читает указанные `AGENTS.md`, архитектурные/UI-правила, локальные навыки и конфиги проверок. Пробел или противоречие возвращает как `blocked`.
2. Проверяет установленный картой runtime-контракт, точный Figma-контекст и кандидатов на переиспользование. Расхождение, которое меняет область, возвращает как `scope_change_required` до редактирования.
3. Реализует минимальную дельту только в `allowed_paths`, не создаёт новый механизм снимков и не вводит новую абстракцию без доказанного повторного использования.
4. Записывает только затронутые снимки штатным способом проекта, затем запускает проверочный режим и остальные обязательные проверки из шлюза.
5. Проверяет фактический diff и возвращает изменённые файлы, применённые правила с источниками, состояния/контексты, команды и результаты проверок, пути к снимкам и остаточные риски. Не коммитит и не создаёт PR.

Агент возвращает `implemented`, `scope_change_required`, `tooling_gap`, `blocked` или `failed`. `scope_change_required` содержит дополнительные буквальные пути и доказательство необходимости; до нового пакета эти файлы не меняются. Оркестратор независимо сверяет фактический diff с `allowed_paths`, а запущенные проверки — с `platform_gate`.

## Завершение

`draft_ready` дополнительно возвращает checkout, ветку и базовую ревизию каждой платформы. `delivered` означает: все выбранные платформы прошли платформенный шлюз, имеют опубликованный `review-only` PR, проверяемые снимки, дизайн-ревью без blocker/high и назначенного внешнего разработчика. Иначе итог — `partial` или `blocked`, даже если часть PR создана.
