# Платформенный шлюз до реализации

Агент не пишет код по общим представлениям о iOS, Android или Web. До первой правки он доказывает, что понимает действующий контракт конкретного проекта: откуда интерфейс получает состояние и окружение, что можно переиспользовать и как результат будет проверен.

Шлюз обязателен для любой интерфейсной задачи и каждой затронутой платформы. Тема — только один из возможных контекстов.

## Что установить

1. **Правила проекта.** Найди все применимые `AGENTS.md` от корня checkout до изменяемых файлов, связанные архитектурные документы, локальные UI/дизайн-системные навыки и конфиги проверок. Для каждого источника укажи точный путь и ревизию. Названия навыков могут меняться: используй найденные текущие документы или их преемников.
2. **Контракт исполнения.** Для каждого свойства, влияющего на результат, определи источник истины во время работы приложения: компонент, дизайн-система, тема приложения, локальный провайдер, операционная система, браузер, сервер или данные экрана. Зафиксируй владельца состояния и цепочку допустимых переопределений.
3. **Переиспользование.** Подтверди существующий компонент, токен, стиль, модификатор, ближайший актуальный паттерн и семейство тестов. Внешнее сходство не доказывает правильный контракт. Не переноси архитектурный приём между платформами без локального подтверждения.
4. **Матрица сценариев.** Перечисли обязательные состояния и значимые контексты: тема, размер, данные, локаль, направление письма, масштаб текста, доступность, reduced motion, контраст, режим ввода, навигация, загрузка и ошибки — только те, которые могут изменить результат этой задачи.
5. **Путь проверки.** До кода найди штатные команды форматирования, анализа, сборки, тестов и снимков. Выполни безопасную предварительную проверку среды: доступны ли зависимости, SDK, симулятор/эмулятор/браузер и хранилище снимков. Недостающий доступ — `tooling_gap`, а не разрешение реализовать вслепую.

## Перекрёстные сценарии

Если приложение или локальный контейнер может переопределить внешний сигнал, проверь оба направления:

```text
внешнее окружение A + локальный контекст B
внешнее окружение B + локальный контекст A
```

Это правило применяется не только к теме: используй его для локали, масштаба текста, направления письма, reduced motion, контраста, размерного класса, breakpoint и других переопределяемых параметров, когда они влияют на задачу. Не строй полное декартово произведение несвязанных условий.

## Платформенные примеры одного правила

- **Android:** если компонент живёт внутри `TravelTheme`, источником должна быть фактически установленная палитра или явно переданный контракт, а не `isSystemInDarkTheme()`, если проект не требует обратного. Для темы проверь «светлая система + локальная `darkColors()`» и «тёмная система + локальная light-палитра». Перед Compose-правками прочитай найденные в проекте `travel-android-architecture` и `how-to-ui` либо их актуальные преемники.
- **iOS:** различай системные `UITraitCollection`/`colorScheme` и явно внедрённую тему или environment-контекст приложения. Если локальная тема допустима, проверь её при противоположном системном оформлении в обе стороны.
- **Web:** различай `prefers-color-scheme` и фактическую тему приложения (`ThemeProvider`, класс или `data-theme`). Если приложение переопределяет системное предпочтение, проверь обе противоположные комбинации.

Примеры не задают технологию заранее. Источник истины всегда подтверждается текущим кодом и правилами выбранного проекта.

## Решение шлюза

Для каждой платформы верни:

```yaml
status: ready | blocked
sources_read:
  - exact path or skill @ revision
runtime_contract:
  property: source of truth and override chain
reuse_plan:
  component: exact path
  tokens_or_styles: exact names
scenario_matrix:
  - state + context + expected result + test/snapshot
allowed_paths:
  - exact file path
verification:
  build: command + preflight result
  tests: command + preflight result
  snapshots: command + preflight result
gaps: []
```

`ready` запрещён, если хотя бы один значимый источник состояния не установлен, обязательный перекрёстный сценарий отсутствует, источники противоречат друг другу или штатный путь проверки нельзя запустить в текущей среде.

Перед возвратом `implemented` исполнитель запускает штатные проверки из шлюза. Незапущенную проверку отмечает как неподтверждённую с причиной; не выдаёт её за пройденную.
