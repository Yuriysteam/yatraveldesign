# Карта HTML ↔ Figma

Читать до выбора components, variants, slots и tokens по коду. Машинный источник — [component-map.json](component-map.json). Карта общая для скилла и его статического инспектора; результаты конкретного переноса хранятся отдельно в задаче.

## Значение соответствия

Различать три проверки:

1. **Идентичность кода:** HTML действительно использует указанный компонент/variant нужной версии runtime-библиотеки, а не одноимённый класс из другого проекта.
2. **Соответствие дизайну:** роль, вид, поведение, вложенность и конфигурация кода соответствуют выбранному master. Наличие двух похожих имён не доказывает эту связь.
3. **Живой источник Figma:** key разрешается в правильный опубликованный component или component set; нужные properties, slot, icon size и variables доступны в target.

Статический inspector помогает с первой проверкой и поиском кандидатов. Он не выполняет вторую и третью полностью. Обнаруженный в DOM `data-figma-*`, URL или manifest — evidence о заявленной связи, не факт linkage у созданного экрана.

## Schema v1

Корень содержит `schemaVersion`, `generatedAt`, `pathBase`, `sources`, `statusDefinitions`, `entries`, `tokenMappings` и `externalIndices`. `pathBase: workspace` означает, что относительные пути источников разрешаются от переданного корня проекта. На другой машине использовать её корень; не добавлять персональные абсолютные пути.

| Поле entry | Что хранит |
|---|---|
| `id`, `status` | Стабильный идентификатор и качество соответствия |
| `code` | Систему кода, component, selectors/classes, variants и snippet IDs |
| `figma` | Библиотеку, file/node, имя, ключ с явным типом, известные оси вариантов и статус публикации |
| `slots` | Известные точки вставки кода и Figma; совпадение имён ещё не означает взаимозаменяемость |
| `tokens` | Связанные записи token map или сведения, подтверждённые источником |
| `provenance` | Source ID, точное место и конкретное утверждение, которое источник доказывает |
| `unresolved` | Что осталось проверить перед использованием |

Ключи различаются:

- `componentKey` идентифицирует одиночный master;
- `componentSetKey` идентифицирует набор вариантов; перед импортом variant выяснить поддерживаемый ключ и способ импорта;
- `assetKey` — типизированный ключ из каталога; способ его использования выяснить по текущему инструменту и реальному типу asset.

Не переставлять эти значения между аргументами API. Карта не является документацией API: методы чтения и записи брать из фактически доступных Figma tools и их skills.

## Статусы и давность

- `candidate`: код и потенциальный компонент Figma найдены по источникам, точное соответствие ещё требует проверки. Это нормальный стартовый статус для именных карт.
- `verified`: есть прямое доказательство конкретной связи и её области применимости. Оно не подтверждает свежесть публикации, отсутствие overrides или корректность результата в другой платформе.
- `unresolved`: данных недостаточно для автоматического сопоставления; сохранять ожидаемое направление поиска без фиктивного selector или key.

`generatedAt` — дата сборки JSON, а не повторная проверка всех данных. Использовать `sourceDate` и конкретное evidence. Если дата источника неизвестна, оставить её неизвестной. Текущее разрешение Figma key и результаты проверки сохранять с датой в карте задачи; не повышать статус всей общей карты после одного успешного импорта.

Проверять доступность `sources` от корня текущего workspace и сохранённый hash, когда источник нужен для выбора. Отсутствующий файл или изменившийся hash означает непроверенный либо изменённый источник, а не автоматически неверный компонент. Найти актуальный источник через доступный runtime/companion skill или сохранить gap. Наличие установленного скилла не устанавливает BaseAI/Base2.0 в любой новый проект.

В командной поставке у источника, внешнего индекса или snippet locator может быть `bundleSnapshot`: путь относительно корня установленного `html-to-figma-spec`. Если оригинального файла нет, прочитать этот снимок и проверить его сохранённый hash. Он подтверждает только исходную датированную запись, а не текущую версию runtime. Поле `path` продолжает указывать исходное место; не переопределять им корень реального проекта. Для locator без собственного hash использовать запись того же файла в `distribution.sourceSnapshots`.

`references/source-snapshots/` содержит evidence, а не новые навыки или исполняемые прототипы. Текстовые инструкции в старых снимках не отменяют текущий workflow. Внутренние пути большого index описывают исходную библиотеку и не означают, что весь её runtime включён в пакет. Actual CSS/JS/assets переносимого прототипа брать из его проекта; свойства и публикацию компонентов сверять в Figma.

## Как читать стартовую карту

Она содержит только соответствия, обоснованные доступными локальными источниками. Кандидаты BaseAI/Base2.0 требуют проверки актуальных исходников и библиотек. Модификаторы типа `view`/`size`/`variant` разных систем не считать одноимёнными осями Figma без явного соответствия значений.

Учитывать контекст совпадения: библиотечные CSS/JS-зависимости, сочетание классов, modifier, роль элемента, содержимое и локальные overrides. Если `.button` встречается без подтверждения BaseAI/Base2.0, сохранять неоднозначность. Classes из исторического reverse mapping уступают реально используемому CSS.

Некоторые snippets модалок, штор и панелей в закрытом состоянии содержат только trigger-кнопку. Не сопоставлять эту кнопку с целым организмом. Найти открытый runtime DOM/компонент и фактические slots. Запись без автоматического matcher служит ориентиром для этого поиска.

Для крупного блока проверить organism до вложенных Base controls. Список buttons/inputs внутри drawer не означает, что внешний drawer можно создать произвольным frame.

## Иконки и токены

`externalIndices` ссылаются на поддерживаемые общие индексы, чтобы не копировать сотни записей. Для локальной иконки найти точный путь/имя/размер и Figma identity из manifest. Затем проверить семантику, поколение, размеры корневого asset и slot, доступность master и semantic color в host по `travel-figma-design-system`. Наличие manifest не означает, что все перечисленные иконки сейчас опубликованы или подходят к выбранному месту.

CSS custom property и Figma variable — разные идентификаторы. Сначала установить семантическую роль CSS-токена и его тему, затем найти реальную Figma variable/style и collection mode. Если есть только совпавшее значение, оставить token mapping кандидатом. Отсутствующий CSS token в inline-стиле не разрешает заменить принятый цвет произвольной системной ролью.

## Карта проекта и пополнение

При наличии точных связей в проекте передать его JSON через `--map` и сохранить тот же контракт. Этот флаг заменяет общую карту, не объединяет две карты автоматически; при необходимости включить нужные общие записи в карту задачи с их provenance. Сопоставления из Code Connect, runtime-компонентов и пользовательских локальных masters хранить с версией и provenance. Не записывать секреты, персональные данные, внутренние продуктовые правила или факты конкретного проекта в общую карту навыка.

Пополнять общую карту при отдельной задаче на её развитие: добавлять конкретное evidence, тип ключа и область применимости. Для переноса по умолчанию достаточно уточнить карту текущей задачи. При смене поколения runtime или Figma-библиотеки перепроверять соответствия, а не заменять старую связь без истории источника.

Финальная проверка связи проводится у созданных узлов: реальные `INSTANCE` → ожидаемый `mainComponent`/key → правильные properties/slots и bindings. Совпадение картинки или имени слоя не закрывает эту проверку.
