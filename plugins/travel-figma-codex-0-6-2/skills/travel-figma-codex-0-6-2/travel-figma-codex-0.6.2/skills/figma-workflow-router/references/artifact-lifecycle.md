# Жизненный цикл HTML-прототипа и упаковки

Читать этот reference, когда результатом является работающий HTML-прототип, автономная папка или ZIP для передачи.

## Смена артефакта

Если задача прошла цепочку `Figma → спека → локальный прототип → внешняя сборка`, каждый следующий этап использует подтверждённые решения предыдущего. Figma может остаться источником визуального решения, не оставаясь целевым артефактом. После смены результата не требовать Figma-подключение для работы, которая от него больше не зависит.

## Исходники и упаковка

Правка файлов проекта и сборка передаваемого артефакта — разные операции.

- «Не создавай архив» — менять только исходники.
- «Пересобери ZIP» — после правок обновить архив и проверить его.
- «Скачай HTML» — по контексту определить, достаточно ли одного самодостаточного файла или нужна папка с зависимостями; при существенной неоднозначности уточнить.

Не объявлять архив обновлённым, если менялись только исходники.

## Масштаб проверки

Для быстрых визуальных итераций: **правка → одна адресная проверка затронутого → следующий запрос**. Не запускать полный повторный аудит после каждой мелкой правки.

Полную проверку выполнить:

- перед передачей результата;
- после изменения архитектуры;
- после изменения адаптивности;
- после изменения общей системы состояний;
- перед упаковкой для внешнего сервера.

Повторять полную проверку только после нового затрагивающего её изменения или найденной проблемы.

## Сначала механика, затем объём

Для большого числа однотипных экранов или данных сначала собрать минимальный рабочий сценарий, проверить ключевое взаимодействие и получить реакцию пользователя. Масштабировать контент и строить инфраструктуру массового наполнения только после подтверждения механики. Прямая простая операция не должна превращаться в преждевременную платформу.

## Проверка переносимости

Перед внешним размещением проверить:

- относительные пути;
- наличие локальных шрифтов, изображений и иконок;
- отсутствие зависимостей от компьютера автора;
- отсутствие служебной оболочки;
- установленный пользователем предел размера;
- работу из папки и/или через HTTP согласно целевой среде.

Системные панели и safe areas считать частью среды запуска. Зафиксировать, кто ими управляет: браузер, нативный контейнер или сам прототип.
