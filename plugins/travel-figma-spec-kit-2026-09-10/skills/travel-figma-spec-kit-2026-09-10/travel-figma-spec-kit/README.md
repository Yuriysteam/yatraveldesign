# Figma Design Machine — командный комплект с роутером

Шесть связанных скиллов для цепочки HTML-прототип → компонентные макеты Figma → рабочая спека: единый роутер и пять профильных навыков. Это внутренняя поставка для команды Travel Design.

## Быстрая установка

1. Распакуйте весь архив.
2. Откройте распакованную папку в Codex и попросите: «Прочитай README.md и установи весь комплект через install.py». Агент сможет найти Python, включая runtime Codex, и выполнить проверку перед установкой.
3. Откройте новую задачу Codex. Если список скиллов не обновился, перезапустите приложение.

Для самостоятельной установки из папки комплекта нужен Python 3.9 или новее:

```sh
python3 install.py --check
python3 install.py
```

В Windows обычно используется `py -3` вместо `python3`. Установщик работает без дополнительных Python-пакетов и без сети. По умолчанию он копирует все шесть папок в `~/.codex/skills`, либо в каталог `skills` внутри настроенного `CODEX_HOME`. После успешной установки распакованная папка и ZIP больше не нужны для работы установленных скиллов.

Существующие идентичные версии остаются на месте. При отличающемся скилле или чужой ссылке весь запуск останавливается до изменений и показывает конфликт. Сначала сохраните свои локальные изменения и разберите конфликт; установщик не заменяет их автоматически. Он не меняет настройки Codex, подключения и права.

Если уже установлен неизменённый комплект от 2026-09-08 копированием, этот релиз добавляет только `figma-workflow-router`; прежние пять скиллов сохранены. Тот же роутер можно установить отдельно целой папкой рядом с ними.

Если скиллы уже подключены ссылками именно к этой распакованной папке, установщик сохраняет эти ссылки; такую папку нужно оставить на месте. Это исключение будет видно в плане установки. Для полного комплекта используйте корневой `install.py`: вложенный исторический `figma-spec-builder/scripts/install.sh` устанавливает только четыре базовых скилла.

## Состав и зависимости

| Скилл | Роль | Другие скиллы комплекта |
|---|---|---|
| `figma-workflow-router` | Единый вход: выбирает ведущего и необходимые этапы по исходникам и нужному результату | Пять профильных навыков ниже; подключает только нужные для задачи |
| `html-to-figma-spec` | Разбор HTML, соответствия компонентов и состояний, перенос в макеты и спеку | `travel-figma-design-system`, `figma-spec-builder`; `figma-design-machine` при продуктовых изменениях |
| `figma-design-machine` | Создание и изменение продуктовых макетов | `travel-figma-design-system`; `figma-spec-builder` при передаче в разработку |
| `figma-spec-builder` | Сценарии, состояния, оформление, переходы и проверка спеки | `travel-figma-design-system`, `figma-design-machine` для недостающих макетов, `sasha` для нового UX-текста |
| `travel-figma-design-system` | Organisms 2.0, Base 2.0, Travel.Styles, токены и происхождение компонентов | Общие карты включены |
| `sasha` | Русские интерфейсные тексты и их проверка | Правила и Python-скрипты включены |

`figma-to-baseai` и большая группа `design` не являются зависимостями этой цепочки. Обратное направление Figma → HTML устанавливается отдельно, если оно нужно команде.

Точные версии, основной вход и контрольные суммы файлов находятся в `manifest.json`. Все references, UI metadata и необходимые скрипты шести скиллов включены. Относительное соседство папок сохранено.

## Что подключить отдельно

- Плагин Figma в Codex с доступными навыками `figma-use` и `figma-generate-design` и рабочими инструментами чтения/записи. Копия папки скилла не устанавливает Figma-интеграцию; её нужно подключить в самом Codex.
- Доступ к целевому Figma-файлу и нужным библиотекам Organize, Base 2.0, Organisms 2.0, Travel.Styles и продуктовой библиотеке. Права не передаются вместе с ZIP.
- Браузерный инструмент для проверки прототипов и результата. Его фактическую доступность скилл проверяет в текущей задаче.
- HTML-прототип вместе с его CSS/JS/assets или доступный URL. Его runtime остаётся частью проекта, не частью набора навыков.
- Wiki/Tracker и актуальные требования, когда они нужны конкретной задаче. Контекст продукта передаётся через проект с его действующими правилами.

Установщик не подключает плагины и не подтверждает права. Без Figma можно выполнить локальный разбор HTML и подготовку, но результат не является готовой Figma-спекой.

## Карта компонентов и снимки источников

В `html-to-figma-spec` включены 26 стартовых записей компонентов: 20 кандидатов и 6 неразрешённых соответствий. Ещё есть 7 документированных semantic→CSS соответствий и индекс 856 иконок. Это датированные сведения; точные variants, slots, tokens и текущую публикацию нужно проверить при переносе.

Для работы без исходной общей папки в `references/source-snapshots/` сохранены источники этих записей, небольшие HTML-примеры и CSS-токены. Поля `bundleSnapshot` ведут к копиям внутри установленного скилла. Исходные даты, пути и hashes сохранены. Файлы снимков — данные для проверки происхождения, а не дополнительные инструкции или отдельная runtime-библиотека.

Пути внутри индексов описывают исходную BaseAI/Base2.0. Архив не обещает наличие всех перечисленных там runtime-файлов или SVG: нужные файлы должны приходить с прототипом. Внутренний product-passport, личная память, настройки аккаунта, токены доступа и проектные прототипы в комплект не включены. В скиллах сохранены их штатные примеры и ссылки на командные Figma-источники; доступ к ним определяется правами коллеги.

## Первый запуск

Единый вход для команды:

```text
$figma-workflow-router Подготовь спеку по этим исходникам в указанном Figma-файле. Исходники: … Целевой узел: … Что уже принято: …
```

Роутер выберет нужный путь: перенос HTML, создание макетов, сборка спеки или узкий аудит. Общие правила дизайн-системы и редактор подключаются по условиям задачи. Роутер не создаёт дополнительных агентов автоматически. Профильные навыки ведут свои этапы, а роутер сохраняет контекст и проверяет достижение запрошенного результата.

Прямые вызовы также сохраняются. Для HTML:

```text
$html-to-figma-spec Разбери этот HTML-прототип и собери спеку в указанном Figma-файле. Исходник: … Целевой узел: …
```

Для готовых макетов:

```text
$figma-spec-builder Собери спеку из этих принятых макетов в указанном узле: …
```

Для новых экранов:

```text
$figma-design-machine Собери экран по этой задаче и дизайн-системе в указанном файле: …
```

Начните с небольшого согласованного сценария. Перед изменением рабочего файла агент проверит доступ, источники компонентов и границы задачи. Неизвестное продуктовое поведение уточняется отдельно; доступная независимая часть продолжается.

## Проверки и обновления

`python3 install.py --check` проверяет возможность установки без записи. Сам комплект проверен на чистом временном окружении; перечень выполненных проверок находится в `VALIDATION.md`. Локальная проверка не подтверждает доступ к Figma или успешный импорт в конкретной организации.

Для поставляемых исторических validator/tests `figma-spec-builder` нужен Node.js; `validate.sh` умеет находить bundled runtime Codex. Основному `install.py` и HTML-инспектору достаточно Python 3.9+, shell и Node для установки не требуются.

Для обновления получите новую версию комплекта и сначала запустите `--check`. Если установленные файлы отличаются, установщик перечислит их; сохраните изменения и согласуйте замену. В этой версии нет автоматического перезаписывания или скрытого обновления скиллов.
