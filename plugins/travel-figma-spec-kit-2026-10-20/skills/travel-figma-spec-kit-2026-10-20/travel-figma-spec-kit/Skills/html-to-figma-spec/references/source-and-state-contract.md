# Исходник и состояния

Читать при разборе HTML, URL и поведения до реконструкции экранов.

## Что проверить в коде

- Точку входа и зависимости: CSS, JS, импортируемые компоненты, assets, шрифты, responsive rules. Для root-relative `/BaseAI/` и `/Base2.0/` проверить, что корнем сервера служит проект, и передать его инспектору через `--web-root`. Если dev server использует другой mount/base URL, выяснить его по конфигурации; не угадывать путь. `--workspace` ограничивает чтение локальных зависимостей и сам по себе не задаёт document root.
- Компоненты: runtime-библиотека, classes/modifiers/data-атрибуты, actual template, variant props, слоты и вложенные controls. В BaseAI provenance Storybook помогает найти код; сама по себе ссылка на Storybook не доказывает Figma identity.
- Переопределения: порядок CSS, локальные правила, inline styles, CSS custom properties, изменённые размеры и скрытые части. Совпадение `.button` или `.input` в произвольном проекте не означает BaseAI/Base2.0.
- Условия: роли, выбранные значения, условные ветки рендера, listeners и состояния загрузки/ошибок. Для длинного bundle искать по конкретным selectors и действиям; не загружать весь bundle без необходимости.

Инспектор даёт стартовый inventory. Он не рассчитывает cascade/computed styles, не выполняет импорты приложения или JavaScript, не проверяет видимость и доступность в браузере, не извлекает все возможные runtime-состояния. Указанный в коде key — заявленная связь, которую нужно разрешить в Figma.

Пустой `labelHint` не доказывает отсутствие подписи: проверить внешний или оборачивающий `label` и доступное имя в браузере. Пустой `declaredActions` не доказывает отсутствие listeners в JS; состояние может присутствовать в `declaredStates` без отдельной записи в `elements`.

В JSON: `elements` содержит selectors и `componentMatches`, `declaredStates`/`declaredActions` — HTML-декларации, `dependencies` — прочитанные и неразрешённые подключения, `cssHints`/`inlineOverrides` — CSS-наблюдения, `figmaAnnotationHints` — заявленные Figma-ссылки, `unresolved`/`limitations` — границы разбора. Внешние icon indices и token mappings общей карты разрешаются на следующем этапе по [контракту соответствий](component-mapping.md); скрипт не разворачивает их в проверенные Figma bindings.

## Проверка в браузере

Использовать доступный в сессии инструмент браузера. Открыть локальный прототип через существующий или минимальный сервер проекта, когда требуются root-relative assets и модули. Для URL проверить доступность и нужную версию. Не устанавливать новую инфраструктуру ради статической страницы без необходимости.

На одинаковом viewport воспроизвести релевантные шаги: вход, главное действие, открытия и закрытия, переключения, ввод, валидация, scroll и конечный экран. Hidden DOM не равен увиденному состоянию. Один screenshot не подтверждает обработку ошибок, сохранение или адаптивность.

Не выполнять действия, отправляющие сообщения или изменяющие реальные данные внешней системы, под видом проверки прототипа без соответствующей авторизации. Использовать демонстрационные данные и доступные тестовые состояния; оставшееся обозначить как непроверенное.

## Реестр сценариев

Для значимого правила сохранить:

| Поле | Содержание |
|---|---|
| Сценарий / state | Одно продуктовое действие или независимое состояние |
| Условие и действие | Начальные данные, роль, trigger |
| Результат | Изменение интерфейса, сохранение/сброс, возврат или конечный экран — только если известны |
| Источник | Файл и selector/строка, наблюдение браузера, точный раздел требований или решение пользователя |
| Статус | `confirmed`, `observed`, `declared`, `unknown`, `out_of_scope` |
| Покрытие | Итоговый frame/node либо конкретный gap |

Значения статусов:

- `confirmed`: поведение подтверждено актуальным согласованным источником в названных границах.
- `observed`: воспроизведено в конкретной версии прототипа; продуктовый контракт этим автоматически не подтверждается.
- `declared`: присутствует в коде, атрибуте или комментарии; ещё не воспроизведено и не подтверждено требованиями.
- `unknown`: нет достаточного источника или источники конфликтуют; сохранять точный вопрос.
- `out_of_scope`: исключено явной границей задачи; отсутствие evidence само по себе не является исключением.

При передаче в реестр `figma-spec-builder`: `confirmed` → «подтверждено», `unknown` → «неизвестно», `out_of_scope` → «неприменимо» только в зафиксированной области. `observed` и `declared` сохранять как основания с оговоркой; не повышать их до подтверждённой продуктовой семантики автоматически.

Не размножать кадры ради всех найденных CSS-классов. Показывать отличия, которые меняют реализацию, действие пользователя или проверку QA. Loading/error/empty, короткий/длинный контент и границы ввода включать по риску и подтверждённой области; предлагаемые новые состояния отделять от уже принятых.

## Артефакты задачи

`html-inventory.json` хранит исходный статический результат. При существенном переносе рядом вести одну компактную карту подтверждённых component mappings и состояний — JSON или Markdown по удобству задачи. Не создавать отдельный большой справочник «контракт прототипа» на канвасе по умолчанию: полезные пояснения размещает сборщик спек у соответствующих экранов.

Сохранять версию источника, viewport и дату наблюдения. Для повторного переноса сначала проверить изменённые HTML/CSS/JS и прежние соответствия, затем обновлять только затронутую часть target.
