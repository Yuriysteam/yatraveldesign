# makedesign — Pixel-Perfect Прототип из Figma

**Жёсткие ограничения (на ВСЕХ шагах):**
- Только чистый CSS в `<style>`. Tailwind и фреймворки запрещены.
- Токены `var(--)` из `Base2.0/tokens/tokens.css` — единственный источник цветов, типографики, скруглений, теней.
- Emoji запрещены — только SVG-иконки.
- Файл: `{person_dir}/{stream}/{filename}.html` или `Base2.0/{stream}/{filename}.html`. Не в корне.
- В `<style>` ЗАПРЕЩЕНО дублировать: @font-face, reset, body, .header, .footer, классы из таблицы маппинга.
- Auto Layout из Figma → верстать ТОЛЬКО через flex/gap. `position: absolute` — только оверлеи, тосты, sticky.

## Шаг 2: Получение данных из Figma

### Шаг 2.0: Каскадная стратегия (ОБЯЗАТЕЛЬНО перед вызовами)

**Сначала** вызови `get_metadata` для root nodeId — получи список дочерних секций и их nodeId.

Затем оцени размер фрейма:
- Если фрейм — **целая страница** (header + sidebar + content + footer): вызывай `get_design_context` **отдельно для каждой ключевой секции** (не для root), чтобы избежать файлов >20KB.
- Если фрейм — **отдельный компонент / модалка / оверлей**: вызывай `get_design_context` для root напрямую.

**Правило размера:** если `get_design_context` вернул файл >20KB — не читать целиком. Вместо этого:
```
Grep "componentName" в сохранённом файле → имена компонентов
Grep "variantProperties" в файле → варианты (Solid/Outlined, Primary/Secondary...)
Grep нужного компонента (напр. "Input") → все его вхождения
```

### Шаг 2.1: Основные вызовы (параллельно)

1. **get_metadata** — `nodeId`: root ID → структура и дочерние nodeId
2. **get_screenshot** — `nodeId`: root ID → общий вид для layout
3. **get_variable_defs** — `nodeId`: root ID → реальные токены как приоритетный источник
4. **get_design_context** — для каждой **нужной секции** отдельно (не root если страница большая)
   - `clientLanguages`: `html,css`
   - `clientFrameworks`: `unknown`
   - `artifactType`: `WEB_PAGE_OR_APP_SCREEN`
   - `dirForAssetWrites`: `{workspace}/Base2.0/assets`

### Шаг 2.2: Извлечение componentName (ОБЯЗАТЕЛЬНО)

После получения `get_design_context` — для **каждого интерактивного элемента** (инпуты, кнопки, тоглы, дропдауны) явно выпиши:

```
Элемент: {описание}
  componentName: {точное имя из Figma}
  variantProperties: {вариант — Solid/Outlined/Primary/Secondary/...}
  → CSS-класс: .{класс из таблицы маппинга Шага 4}
```

**Запрещено:** определять компонент по скриншоту или внешнему виду. Только по `componentName` из `get_design_context`.

### Шаг 2.3: Проверка полноты данных

- Если `get_design_context` вернул меньше секций чем видно на скриншоте → вызови `get_metadata` для дочерних nodeId, затем `get_design_context` для каждой секции отдельно. Не продолжай с неполными данными.
- Если ошибка записи ассетов («file already exists» / пустой ответ) → повтори без `dirForAssetWrites`. Если снова ошибка → запроси CSS из Figma Dev Mode.

## Шаг 4: Маппинг компонентов на дизайн-систему

**ПРАВИЛО:** маппинг — ТОЛЬКО по `componentName` и `variantProperties` из `get_design_context`.

Пример правильного маппинга:
- `componentName: "Input"` + `variantProperties: { Style: "Solid" }` → `.input-solid` ✓

## Шаг 5: Маппинг иконок и ассетов (Glob-проверка ОБЯЗАТЕЛЬНА)

### 5.1. Иконки

Библиотека: `Base2.0/icons/{6,8,10,12,14,16,20,24,32,36}/`, нейминг PascalCase.

Для каждой иконки из Figma — **выполни Glob ДО написания HTML**:

```
1. Имя и размер из componentName / get_metadata
2. Нормализуй: kebab-case → PascalCase, убери размер из имени
3. Алиасы: close→Cross, back→ArrowLeft, chevron-right→ChevronRight,
   chevron-down→ChevronBottom, search→MagnifyingGlass, settings→Settings,
   edit→Pencil, delete→Trash, favorite→HeartOutline, share→Share
4. Glob: Base2.0/icons/{size}/{Name}.svg
   ✓ найден → <img src="{prefix}/Base2.0/icons/{size}/{Name}.svg">
   ✗ не найден → inline SVG из get_design_context
```

**Запрещено:** писать путь к иконке без предварительной Glob-проверки.
**Запрещено:** сохранять иконки в `assets/` — только в `Base2.0/icons/`.

Результат фиксируй в инвентаризации (Шаг 3.1) со статусом ✓/✗.

### 5.2. Ассеты (не иконки)

Перед каждым `<img>` из Figma — каскад проверки:

```
[ ] Это иконка? → см. §5.1, НЕ в assets
[ ] Логотип Яндекса? → assets/logos/logo-yandex.svg / logo-sign.svg / logo-text.svg
[ ] Аватар? → Glob assets/avatars/* → любой найденный
[ ] Сервис-иконка (авиа/жд/отель/трансфер)? → Glob assets/service-icons/*
[ ] Фото города/отеля? → Glob assets/photos/* → по размеру похожее
[ ] Иллюстрация/баннер? → Glob assets/illustrations/* → проверить похожую
[ ] Ничего не подошло → сохранить через MCP
```

**Категория-папки обязательны** (плоское сохранение в корень `assets/` запрещено):
- `assets/avatars/` — портретные изображения
- `assets/photos/` — фото отелей, городов, транспорта
- `assets/service-icons/` — иконки сервисов
- `assets/illustrations/` — баннеры, иллюстрации, empty-states
- `assets/logos/` — логотипы

### 5.3. Запрет хеш-имён

- ✓ Латиница, kebab-case: `room-bed-double.svg`, `hotel-balcony-01.png`
- ✗ Запрещены SHA-имена вида `a48e61edb99211f4685e797be1886bbcb42b241b.svg`

После сохранения MCP:
1. Если файл с хеш-именем → сразу переименовать в осмысленное
2. Перед переименованием проверить (md5/sha) — нет ли файла с таким содержимым в assets/ (если есть — использовать существующий, новый удалить)
3. Обновить путь в HTML

### HTML-шаблон (ОБЯЗАТЕЛЬНО: базируйся на Base2.0/templates/)

**Перед написанием HTML — проверь и используй canonical шаблон из `Base2.0/templates/`:**

| Стрим | Шаблон | Что в нём уже есть |
|-------|--------|---------------------|
| B2B | `Base2.0/templates/_layout-B2B.html` | header, sidebar с меню, footer, respons |
| B2C | `Base2.0/templates/_layout-B2C.html` | header с gradient, user-panel |
| App | `Base2.0/templates/_layout-App.html` | phone-frame, app-header, анимационные vars |
| Extranet | `Base2.0/templates/_layout-Extranet.html` | left-menu, top-nav |
| Academ | `Base2.0/templates/_layout-Academ.html` | top header с навигацией |

**Правило templates-lookup (перед генерацией):**

```
1. Glob: Base2.0/templates/_layout-{stream}.html
   ✓ найден → скопировать в {person_dir}/{stream}/{filename}.html
   ✗ не найден → запросить у пользователя, нужно ли создать новый canonical шаблон
2. Glob: {person_dir}/{stream}/*.html
   Если есть похожая страница (тот же стрим, близкий скоп) — предложить пользователю
   использовать её как базу вместо шаблона.
3. Никогда не начинать HTML с нуля, если есть canonical шаблон или похожая страница.
```

**Пути в шаблоне — всегда абсолютные:** `/Base2.0/tokens/tokens.css`, `/Base2.0/styles/fonts.css`, `/Base2.0/styles/components.css`, `/Base2.0/assets/...`, `/Base2.0/icons/{size}/...`.

В `<style>` шаблона: reset, body, header, sidebar, footer — **уже есть**.
Шрифты подключены через `/Base2.0/styles/fonts.css` — **НЕ добавлять `@font-face`**.
Добавляй ТОЛЬКО page-specific стили. **Запрещено** дублировать уже присутствующее.

Минимальная структура нового файла:
```html
<!DOCTYPE html> <!-- взять из Base2.0/templates/_layout-{stream}.html -->
...
<style>
  /* ТОЛЬКО стили для нового контента страницы */
  /* Никаких @font-face, reset, body, .header, .footer, .sidebar */
</style>
...
<body>
  <div class="page">
    <!-- хедер/сайдбар/футер из templates/_layout-{stream}.html — НЕ менять -->

    <div class="main-content">
      <!-- PAGE CONTENT — сюда вставлять контент страницы -->
    </div>
  </div>
</body>
```

**App**: phone-frame обёртка и `.app-header` уже в шаблоне. Добавляй content внутрь `.phone-frame` после хедера.

## Шаг 7: Layout-правила

### Auto Layout → Flexbox

| Figma Auto Layout | CSS |
|---|---|
| direction: horizontal | `display: flex; flex-direction: row;` |
| direction: vertical | `display: flex; flex-direction: column;` |
| spacing: N | `gap: {токен или Npx};` |
| padding: T R B L | `padding: T R B L;` |
| alignment: center | `align-items: center;` |
| alignment: space-between | `justify-content: space-between;` |
| wrap | `flex-wrap: wrap;` |
| fill container | `flex: 1;` или `width: 100%;` |
| hug contents | `width: fit-content;` |
| columns N | `display: grid; grid-template-columns: repeat(N, 1fr);` |

**Запрещено:** `position: absolute` внутри Auto Layout. Исключения: оверлеи, тосты, sticky, декор поверх контента.

### Фильтрация Figma-артефактов (ОБЯЗАТЕЛЬНО)

Figma часто генерирует избыточный CSS — **всегда нормализуй**:

| Figma-артефакт | Что делать |
|---|---|
| `position: absolute` у секций страницы (header/content/footer) | → заменить на flex-item в колонке `.phone-frame` / `.page` |
| `width: 375px` / `width: 1440px` (фиксированная ширина фрейма) | → заменить на `width: 100%` |
| `left: 0; right: 0` на дочернем элементе | → убрать, использовать `width: 100%` или flex |
| Зазор между секциями через `top: Y` | → вычислить разницу координат из `get_metadata` → `margin-top: Npx` или `gap` на родителе |
| `<button>` без явного фона в дизайне | → всегда добавлять `border: none; background: none;` |

**App phone-frame:** всегда `display: flex; flex-direction: column`. Секции (status-bar, toolbar, filterbar, content) — flex-items с `flex-shrink: 0`. Контентная область — `flex: 1`. Floating-элементы (кнопки поверх контента) — единственное законное применение `position: absolute` внутри frame.

## Шаг 10: Проверка в браузере — Pixel-Perfect Diff

### Шаг 11.0: Подготовка браузера

```bash
# Закрыть Chrome если запущен (иначе Playwright не может подключиться)
pkill -f "Google Chrome" 2>/dev/null; sleep 1

# Запустить сервер если не запущен
python3 -m http.server 2026 &
```

Затем вызови `browser_navigate`. Если ошибка запуска → `browser_install`, затем повтори `browser_navigate`. Если снова ошибка → сообщи пользователю запустить Chrome вручную и открыть `http://localhost:2026/{stream}/{filename}.html`.

### Шаг 11.1: Снимок и сравнение

1. `browser_resize` width=1440, height=900 (App: width=375, height=812)
2. `browser_navigate` → `http://localhost:2026/{stream}/{filename}.html`
3. `browser_take_screenshot` → сохранить в `.temp/{filename}-vN.png`
4. Сравни со скриншотом Figma из Шага 2. **Обязательный diff-чеклист:**
   ```
   [ ] Количество секций совпадает
   [ ] Ширина контентной области совпадает
   [ ] Шрифты загружены — YS Text / YS Display (не Arial / sans-serif)
   [ ] Все иконки отображаются (нет битых src, нет квадратиков)
   [ ] Размеры заголовков совпадают
   [ ] Отступы между секциями совпадают (±2px)
   [ ] Размеры карточек / кнопок совпадают
   [ ] Цвета фонов и текста совпадают
   [ ] Хедер и футер на месте (для десктоп)
   [ ] Нет горизонтального скролла
   ```
5. **Перечисли каждое расхождение явно** в формате:
   - Элемент: `{название}` — {что не так} ({на сколько px / какой цвет})

   Если расхождений нет → написать **«Расхождений нет»**.
6. Если есть расхождения >2px → внести правки и повторить пункты 2–5.
   **Повторять до «Расхождений нет».**
