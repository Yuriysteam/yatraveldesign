# Настройка общего репозитория

1. Создайте пустой приватный репозиторий во внутреннем Git-сервисе.
2. Ограничьте доступ командой, которой разрешён продуктовый контекст.
3. Защитите ветку `main`: изменения только через pull/merge request, минимум один review.
4. Добавьте обязательную проверку `bash scripts/validate.sh` и запретите merge при её падении.
5. Не подключайте публичные зеркала, Pages и внешние CI-интеграции без отдельного согласования.

После публикации коллега клонирует репозиторий и один раз запускает `bash install.sh`. Установка связывает глобальный `$travel-product-context` с клоном, поэтому обычный `git pull` обновляет базу без повторной установки.

ZIP оставьте резервным способом передачи. Для совместного редактирования используйте Git: собственные правки возвращаются через ветку и pull/merge request по правилам `CONTRIBUTING.md`.
