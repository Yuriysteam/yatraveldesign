# Статические сценарии Путешествий

Откройте `index.html`: на общей странице расположены отели, авиа и ж/д, по четыре настоящих HTML-состояния в каждом сценарии.

- Отели: `01-home/`, `02-results/`, `03-hotel/`, `04-checkout/`.
- Авиа: `avia/01-home/`, `avia/02-results/`, `avia/03-details/`, `avia/04-checkout/`.
- Ж/д: `trains/01-home/`, `trains/02-results/`, `trains/03-details/`, `trains/04-checkout/`.

В каждой папке лежат `index.html`, локальные ресурсы `assets/`, источник `source.json` и контрольное изображение `preview.png`. Сама страница — реальная разметка Travel, не скриншот. Светлая тема и светлые изображения логотипов зафиксированы независимо от темы системы. Скрипты, внешние запросы и отправка форм отключены; бизнес-логика не выполняется.

## Обновление

Из этой папки:

```bash
node update-all.mjs
```

Можно обновить выбранные сценарии:

```bash
node update-all.mjs avia trains
node update.mjs
```

Последняя команда обновляет только отели. `./update` также запускает общее обновление. `update-transport.mjs avia` и `update-transport.mjs trains` — отдельные сборщики транспортных сценариев.

Параметры отеля находятся в `scenario.json`, транспортных маршрутов — в `transport.json`. Даты вычисляются относительно дня запуска; по умолчанию выезд через 19 дней, в отеле две ночи. Каждый набор сначала собирается во временной папке и проверяется браузером с заблокированной внешней сетью, затем заменяет соответствующие четыре папки. При недоступности нужного рейса, места или страницы сборщик останавливается без искусственной замены интерфейса.

Нужны интернет, Node.js 20+, Python 3 и установленный подготовленный Playwright CLI из `~/.agents/skills/playwright-cli`. Другой путь задаётся переменной `PLAYWRIGHT_CLI_SKILL_DIR`. Браузер автоматически не устанавливается. Используется публичный интерфейс `playwright_runtime.mjs` установленного инструмента.

## Происхождение и границы

Отели: главная → выдача Москвы → The St. Regis Москва Никольская с номерами и тарифами → оформление первого доступного номера.

Авиа: главная → Москва–Сочи → условия выбранного рейса → данные пассажира. В выдаче выбирается партнёр «Яндекс Путешествия», чтобы сохранять собственное оформление Travel, а не страницу стороннего агентства. Третий экран — действительное раскрытое окно условий в выдаче.

Ж/д: главная → Москва–Санкт-Петербург → выбор места в поезде 016А → данные пассажира. Детали открываются по существующему маршруту с корректными ключами городов `c213` и `c2`; выбор свободного места выполняется на живой схеме, до отправки заказа. Выдача сохраняет фактическое состояние публичного сервиса, включая доступность или отсутствие цен. Наличие мест проверяется отдельно на странице выбора.

`manifest.json`, `avia/manifest.json` и `trains/manifest.json` содержат время обновления и результаты проверок. Время захвата и исходные адреса каждой страницы — в её `source.json`. Токены оформления не сохраняются в адресах источников. Исходный проект не пересобирался и не изменялся: сохранены реальные страницы публичного сервиса.

Ни один сборщик не вводит платёжные данные, не нажимает финальную оплату и не отправляет бронирование. После экспорта формы не работают.

## Оформление каталога

Каталог использует сохранённые CSS-компоненты Button UIKit Путешествий, штатные светлые токены и шрифты YS Text / YS Display. Исходные стили извлекаются из настоящей HTML-главной через `python3 tools/build-catalog.py`; это не отдельная React-сборка UIKit. Раскладка каталога находится в `catalog/catalog.css`, переключение сценариев — в `catalog/catalog.js`. Превью открывают исходные HTML-страницы. Общее обновление заново подготавливает CSS и брендовые ресурсы каталога.
